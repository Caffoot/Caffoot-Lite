## Schema 30

The database adds `accounts.must_change_password`, a non-null Boolean flag defaulting to false, and `account_password_change_proofs`, which stores a digest and a five-minute expiry for the restricted change proof. The proof is bound to the current credentials and permission state. Normal sessions remain in `account_sessions`. Existing account identities, passwords, MFA, permissions, email verification and working sessions are retained through the schema 29 → 30 migration. The approved verified-email recovery path can clear the flag with all applicable recovery proofs and a different password. [Technical decisions](https://github.com/Caffoot/Caffoot-Lite/issues/460#issuecomment-7160144717)
