## Focused Verification

- **Checkpoint D.** The Supplier Equipment HTTP test covered original receipt quantities, a second Supplier’s contribution to pooled stock, stock-derived Device exclusion, retirement, issue, return and write-off, independent module access, disabled modules and Supplier retention. The final focused repeat also verified that a disabled company stays linked and that renaming it updates the canonical display while preserving the original receipt text. The Chromium workflow exercised filtering, both canonical destinations, browser Back and restricted views. [Checkpoint D](https://github.com/Caffoot/Caffoot-Lite/commit/d78164b5e64b9c5fa4db6bcc5265c97b3cd735fe).
- **Backend and security.** `PYTHONPATH=tests python -m unittest -q test_suppliers_http test_http_security test_full_import_boundary test_history_permissions` passed 39 tests. These cover equipment and Supplier permission boundaries, stock movement preservation, atomic and replay-safe assignment, Supplier impact and delete checks, published JSON import boundaries and audit visibility. Checkpoint A also tested an in-memory SQLite backup containing the new Device association and retention records.
- **Batch 4.3 Chromium.** `node tests/equipment-suppliers-interface.cjs` exercised the integrated workflows, keyboard choice, typed name, authorised creation, access denial, Device and receipt draft return, feature-off edit preservation, history corrections, filter and drill-down. The capture run checked existing columns and receipt fields, confirmed unchanged assignment dialogs close directly, and checked workspace width in desktop and mobile light and dark.
- **Existing Chromium regressions.** `tests/suppliers-interface.cjs` passed the Supplier, Issue and Purchasing workflows. `tests/stock-intake-interface.cjs` passed receiving, readiness, stock and receipt history, access, retry and feature-switch preservation. Both used isolated local test-server ports. The unmodified stock test reproduced a forced-click timing failure on the setup-only baseline at `7ea68ec089d2d3aa55e6e6d384840b1af0d21793`. Removing the forced action on re-enable let Playwright wait for the existing switch to become actionable. [Verification and responsive refinements](https://github.com/Caffoot/Caffoot-Lite/commit/176c136adf68223653db78e76737295995f4ff23).
