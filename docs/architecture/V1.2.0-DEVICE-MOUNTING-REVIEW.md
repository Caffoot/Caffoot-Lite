# v1.2.0 — Device Mounting and Form Factor Review

Status: proposed design; no application behaviour changed by this document.

## Principles

Physical location (site/building/room), device type (what it is), form factor (physical shape), mounting method (how installed), and rack assignment (specific rack/face/U) are distinct. Never infer a location from mounting. Device-type suggestions should not prevent legitimate uncommon installations. Preserve existing mounting values in backups and avoid silent remapping.

## Server terminology

Keep `Server - Physical` and `Server - Virtual` as types. Tower Server is a conventional description of a physical server's chassis, not necessarily a separate device type. Propose an optional **Form Factor** for physical servers: Rackmount, Tower, Blade, Mini / Compact, Other. A virtual server uses Not Applicable. A blade needs chassis relationships before claiming a full mounting model; defer those relationships.

## Proposed mounting vocabulary

- Desktop / Tabletop
- Shelf Mounted
- Rack Mounted
- Wall Mounted
- Ceiling Mounted
- Pole Mounted
- DIN Rail Mounted
- Under-Desk Mounted
- Floor Standing
- Handheld
- Mobile / Portable
- Vehicle Mounted
- Not Applicable
- Unknown / Not Specified

Keep legacy `Desktop` and `Tabletop / Shelf Mounted` values readable on import and existing records; agree migration/display aliases before changing stored values. Allow user-managed custom mounting types only with explicit validation and rack invariants.

The code's existing `phase19BAllowedMounts` currently restricts desktop/laptop/tablet to Desktop; access points to a special list; other types to Desktop and Rack Mounted. Suggestions above are proposals, not implemented behaviour.

## UX and compatibility requirements

1. Offer type-appropriate options first while allowing valid exceptions and custom types.
2. Only Rack Mounted shows rack placement; physical location stays editable.
3. Virtual devices must not accidentally acquire physical rack assignments.
4. Existing import/export and stored typeDetails values remain compatible.
5. Tests should cover physical tower servers, rack servers, virtual servers, handheld tablets, laptops, access points, custom device types, and legacy mounting values.
6. Do not merge to main until location/rack migration and mounting changes pass automated and browser tests.
