Protect Your Caffoot Data

Real backup guidance, right where you need it — not hidden in a separate manual.

Docker / SQLite

Database Backup Guide

Your saved inventory lives in the persistent /data volume.

Storage Based
01
Locate Your Actual Data Volume

In Portainer, open the Caffoot Lite stack and identify the volume mounted at /data. A Compose-managed volume may have a stack-name prefix.

02
Stop Caffoot Lite Safely

Stop the application before copying the SQLite files, so the backup includes a consistent database.

03
Archive the Data Volume

On a Linux Docker host, identify the volume, then use your actual volume name in the example archive command.

docker volume ls --format '{{.Name}}' | grep caffoot
docker run --rm \
  -v ACTUAL_VOLUME_NAME:/source:ro \
  -v "$PWD":/backup \
  alpine sh -c 'cd /source && tar -czf /backup/caffoot-data-backup.tar.gz .'
04
Secure, Test and Restart

Keep the archive somewhere safe, verify it exists, then restart your stack. Practise restoring to a separate test installation.

Important: Replace ACTUAL_VOLUME_NAME with the verified volume. If you use a bind mount, back up that directory instead. The archive command is for a stopped application, not a live SQLite copy.

Import a supported v1.3.3 JSON file into your Docker edition. Caffoot Lite will show the existing validation, review, corrections and explicit confirmation steps before any replacement.

Storage & Recovery

Keep your existing installation data safe.

A new installation can use Docker's standard named volume. If your current system already uses a bind mount or another volume, do not change that mapping without migrating the data.
