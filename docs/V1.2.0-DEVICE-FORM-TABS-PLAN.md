# v1.2.0 Task 1A — Device Form Tabs

Status: implementation plan; no application code changes yet.

## Agreed tab order

1. **General** — device name, type, status, location, notes.
2. **Hardware** — manufacturer, model, serial number, mounting, rack position and hardware-specific details.
3. **Software & Firmware** — existing software-specific type details; future dependent operating system, edition and firmware fields.
4. **Networking** — IP Address Block, VLAN, subnet, primary IP and reservation status.

Connections are deferred to a later release.

## Current implementation

The shared `openDeviceModal(deviceId = null)` function in `app/caffoot-lite.html` builds Add, Edit and Duplicate Device forms. The form is currently a vertically stacked collection of sections. Device-type-dependent controls are generated by the existing phase19B helpers. The form has an existing 850px maximum width.

## First code increment

Introduce accessible tab buttons and panels in the existing modal, retaining all existing control IDs, values, event handlers and form submission. Keep the action buttons outside the tab panels. Do not change persisted device data, backup format, IPAM logic or rack placement logic.

Critical: native form validation must activate the panel containing an invalid control before focus is moved to it. Tab changes must not recreate form controls or discard unsaved values. Switching type must preserve applicable draft values and must not silently discard incompatible values.

The current nested type-specific section must be classified by field semantics before moving it: software options should not be placed in Hardware merely because that is where the existing markup is nested.

## Acceptance checks

- Add, Edit and Duplicate all work.
- Required-field validation locates and reveals the correct tab.
- Keyboard tabs, arrow keys, Home/End and visible focus work.
- Narrow viewport, light/dark themes and modal Escape/Cancel work.
- Dynamic type fields, create-rack/create-subnet return flows, IPAM allocations and rack limits still work.
- Existing automated tests, offline build and manual PowerShell browser checks pass.

Do not merge until implementation and checks are reviewed.
