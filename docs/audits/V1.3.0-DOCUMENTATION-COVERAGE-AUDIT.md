## WF-01 to WF-02 boundary: verified save and audit sequence, 22 October 2026

Inspected published tag `v1.3.0` in `app/caffoot-lite.html`, functions `saveState()`, `recordAudit()` and `readAuditHistory()`. On a normal save, recovery mode blocks writes; `validateApplicationState()` blocks inconsistent inventory; `saveState()` serialises the inventory, writes `caffoot_state` and checks that reading it back produces identical text. Only after successful main-inventory verification does it attempt `recordAudit()`. Audit records use the separate `caffoot_audit_v1` key and are capped at 200 summary events. ## WF-02 rack accessory placement and persistence, 22 October 2026

Source reviewed from published tag `v1.3.0`, `app/caffoot-lite.html`, approximately lines 1950–1965, 2879–2900, 7970–8020, 8090–8150 and 8270–8295. No tests executed in this audit.

**Physical occupancy:** `phase13CAccessoryError()` distinguishes horizontal accessories from vertical side rail accessories. Horizontal accessories must fit in numbered rack units and avoid device and horizontal accessory overlaps on the same rack face. Vertical types `pdu_vertical` and `cable_vertical` use left or right side rails on a specified face, with collision checks against other vertical accessories sharing that rail and overlapping height ranges. They do not consume horizontal numbered U capacity. The rack overview capacity calculation likewise excludes vertical accessory types when marking occupied numbered U positions. Rack resizing checks mounted devices and accessories against the proposed height. Do not describe vertical 0U items as consuming numbered U capacity.

**Save outcomes:** Accessory create/edit form, delete confirmation, horizontal move and vertical rail drop all capture a serialized prior inventory, call `saveState()` and restore the prior inventory if saving fails. This is a source-level safeguard, not yet verified by injected browser storage failures. Add browser tests for each pathway, including occupied rails, front/rear face independence, cancellation, invalid height and failed persistence.

**Documentation naming opportunity:** `phase13CAccessoryError()` describes validation, not a generic error. A proposed clearer name is `validateRackAccessoryPlacement()`; retain the current identifier in the technical reference until a separately approved refactor. Avoid changing behaviour and naming in the same untested change.

## WF-02 imported inventory validation and restore safety, 22 October 2026

Source inspected at published tag `v1.3.0`, `app/caffoot-lite.html`, approximately lines 7508–7622 and 7693–7849. Source inspection only; no fresh tests executed.

The import handler limits file size to 10 MB, parses JSON, rejects unsafe keys, checks required backup shape and version, reviews incompatible legacy access point mounts before migration, then calls `phase16CCheckBackup()`. That function migrates a detached candidate, rejects unsupported device mounts and temporarily supplies the candidate to `validateApplicationState()` before restoring the active in-memory inventory. It refuses import when integrity errors are returned. Other legacy mounting corrections are presented for user review before the final restore confirmation.

On confirmation, the handler captures the current stored inventory, writes a separate pre-restore safety snapshot and verifies readback. It then saves the candidate, reads back persisted data, normalises it and compares with the candidate. On failure it restores active in-memory state and attempts a verified storage rollback. An unverified rollback activates recovery mode and blocks further saves. Successful restore updates selected subnet and rack and rerenders.

**Important qualification:** Calling `validateApplicationState()` on an imported candidate is broader than simply checking import file shape. However, this source inspection alone does not establish that every historical rack accessory anomaly or cross-face occupancy combination is detected. Inspect the validator's precise accessory checks and migration behaviour before asserting full import collision coverage. Test imported fixtures with overlapping devices/accessories, vertical rail conflicts, missing rack links, legacy mounts, safety snapshot write failures and rollback failures. Do not alter production data during testing.
