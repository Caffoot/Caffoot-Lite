# Caffoot Lite v1.3.1 Maintenance Roadmap

**Status:** Candidate investigation register. No v1.3.1 changes approved or implemented.
**Baseline:** Published v1.3.0, pending exact release commit verification.
**Purpose:** Capture potential defects, missing safeguards and maintenance improvements found while documenting the actual v1.3.0 application. This document does not assert that any candidate is a confirmed defect.

## Rules

- Preserve an accurate description of v1.3.0 in `TECHNICAL-WORKFLOWS.md`; do not silently rewrite historical behaviour.
- Record source evidence, reproduction steps, risk, dependencies and test requirements before confirming an issue.
- Distinguish **Investigation required**, **Confirmed issue**, **Approved for v1.3.1**, **Fixed and verified**, and **Closed without change**.
- Prioritisation and inclusion in v1.3.1 require product owner approval. No application code changes are authorised by this roadmap.
- Keep the published v1.3.0 application untouched unless separate maintenance work is explicitly approved.
- Use British English in public-facing text.

### Additional candidate: M-009 Gateway ownership and subnet editing

**Status:** Investigation required, source-supported scenario, runtime reproduction pending.

The device primary IP helper permits a gateway address on Firewall, Router and Layer 3 Switch devices, while the subnet form rejects any proposed gateway already recorded as a device primary IP or IPAM allocation, including when the gateway value is unchanged. Test whether editing an unrelated subnet field fails when its gateway is legitimately device-owned. Decide and document gateway ownership rules before approving a fix; preserve existing data and add regression tests.

**M-009 additional source evidence:** `phase10GatewaySubnet()` identifies a gateway directly from the subnet record, and `phase10SubnetSummary()` counts an unallocated gateway as reserved without storing an IPAM allocation. `setDevicePrimaryIp()` permits eligible network devices to own a gateway and creates a device-linked allocation. The subnet editor nevertheless rejects any proposed gateway already device-owned or present in IPAM, even when unchanged. Verify via browser testing after documentation; consider legacy and imported inventories before approving behaviour changes.

**M-005 import evidence:** `normaliseState()` and `validateApplicationState()`, both used during backup import, have no explicit `virtualHostId` relationship validation. Test an imported virtual server referring to a missing or no-longer-physical host. Determine desired rejection, warning or controlled recovery behaviour before implementing anything.

**M-009 import evidence:** Imported network gateways are checked for validity and membership in their subnet, but the shared integrity validator does not explicitly enforce permitted device types for a device owning that gateway. Test gateway ownership across imported legacy inventories and manual edits before agreeing one consistent policy.

### M-010: Consistent rack occupancy validation during import

**Status:** Source-supported candidate; browser reproduction and design approval pending.

**Evidence:** The normal rack editing and movement paths use `validateRackPlacement()` and `phase13CAccessoryError()`, but backup normalisation and `validateApplicationState()` do not perform equivalent pairwise device or accessory occupancy checks. Imported accessory records are not comprehensively validated for rack reference, face, bounds and collisions. See WF-05/WF-06 cross-workflow finding in `docs/TECHNICAL-WORKFLOWS.md`.

**Proposed investigation:** Construct disposable backups with two devices on the same rack face and U, overlapping normal accessories, out-of-bounds accessories and invalid 0U rail placements. Check whether import accepts them, whether data remains readable, and whether existing inventory is preserved on rejection. Agree a shared validation policy that respects front/rear separation, legitimate side rails and historic backup compatibility. Do not silently delete or relocate equipment.
