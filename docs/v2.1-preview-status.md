# Caffoot Lite v2.1 — Development preview status

**Not a release.** Source branch: [`v2.1`](https://github.com/Caffoot/Caffoot-Lite/tree/v2.1). Baseline: published v2.0.1. Owner-approved design and functional scope: [#227](https://github.com/Caffoot/Caffoot-Lite/issues/227); current development record: [#229](https://github.com/Caffoot/Caffoot-Lite/pull/229). Future unapproved ideas remain in [#222](https://github.com/Caffoot/Caffoot-Lite/issues/222).

## Implemented through Stage 11

The premium sidebar, Dashboard, Device directory/details, IPAM, Racks, Users, Settings & Data and My Account have been progressed in reviewed stages. The underlying v2.0.1 inventory, role, MFA, editing, Rack/VM Hardware, import and backup workflows are retained unless a feature was explicitly approved.

**Personal Details** are now live: optional first name, last name, email, display name and circular photograph. Optional data is stored in SQLite `account_profiles` (schema 8, linked to existing accounts). Photos are bounded raster uploads, stored in the same database and retrieved only for the signed-in account. Usernames remain read-only. Email is not verified and cannot reset a password.

The most recent completed four-check CI checkpoint for these features is commit `aaf18358a6aae243f5af64baebaefb12af8f9219` on 1 November 2026. These checks are not a substitute for owner-led visual inspection or final release tests.

## Not yet finished

- Email/SMTP settings, verification, secure recovery and approved notifications.
- The approved protected, searchable Audit Trail (the existing Change History remains until implementation).
- Final screen-by-screen review against approved designs, user-facing screenshots, documentation acceptance, upgrade/back-up rehearsals and release candidate checks.
- Production release tagging, v2.1 final image, v2.1 website changes and merge to `main` — all require separate owner acceptance.

The interface may still show `Planned` cards for My Devices and tickets. Those ideas are outside the current approved v2.1 implementation; no assignment/ticket functionality is implied.

## Branch, image and installation rules

- Build preview from this exact branch through [`v21-preview-image.yml`](../.github/workflows/v21-preview-image.yml), subject to passing its backend job.
- Preview image: `ghcr.io/caffoot/caffoot-lite:v2.1-preview` (unreleased test tag), plus an immutable commit SHA preview tag.
- Portainer stack: [`portainer-v2.1-preview.yaml`](../portainer-v2.1-preview.yaml). Uses port **8444** and a dedicated **`caffoot_v21_preview_data`** volume. Replace the illustrative `192.168.1.100` server IP before deploying.
- **Never** use the stable container name, stable host port or stable production data volume in this preview.
- Schema migration is forward-only. Do not run an unfinished preview directly on an irreplaceable v2.0.1 database. Back up the entire production `/data` separately.
- Confirm the GitHub Actions image workflow succeeded and its GHCR package is publicly pullable before pressing Deploy. Deployment must not be taken as release approval.

## Keeping the documentation honest

This branch's README and deployment files describe the **v2.1 preview**. The [v2.0.1-tagged documentation](https://github.com/Caffoot/Caffoot-Lite/blob/v2.0.1/README.md), [v2.0.1 release notes](Release-Notes-v2.0.1.md) and production website remain historical/published material, and must not be renamed to pretend a v2.1 release has shipped. Feature instructions are updated to distinguish current preview behaviour from features that are only approved for future v2.1 work.

Manual owner feedback and preview screenshots will determine the final documentation and design corrections.
