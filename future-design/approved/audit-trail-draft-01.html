Clear, accountable history

Decision needed
Important security boundary: never record passwords, password hashes, MFA seeds or codes, session tokens, API secrets or entire sensitive request bodies. Before/after values should be carefully limited to safe, useful fields. The audit record must remain read-only; this is not a data restore facility.

This page intentionally distinguishes what is recorded today from a possible future specification. In particular, the existing 200-event limit must not be silently increased and new logging must not be implemented just because this visual prototype depicts it. All changes need product-owner approval and migration/backup testing.
