Database Backup Guide

Protect your saved Docker / SQLite data with a consistent backup.

Storage-Based
  1. 01
    Locate Your Data Volume

    In Portainer, open the Caffoot Lite stack and check what is mounted at /data. A Compose volume may have a stack-name prefix. Do not assume the volume's name.

  2. 02
    Stop Caffoot Lite Safely

    Stop the application before copying SQLite database files so your backup is consistent.

  3. 03
    Archive the Verified Volume

    On your Docker host, find the volume name, then replace the example placeholder below with the name you actually found.

    docker volume ls --format '{{.Name}}' | grep caffoot
    docker run --rm \ -v ACTUAL_VOLUME_NAME:/source:ro \ -v "$PWD":/backup \ alpine sh -c 'cd /source && tar -czf /backup/caffoot-data-backup.tar.gz .'
  4. 04
    Secure, Verify & Restart

    Keep the archive somewhere safe, verify it exists, restart your stack and practise restoring to a separate test installation.

Important: Use your verified volume name. If you use a bind mount, back up that directory instead. Never treat the example as a live database backup command.

Storage & Recovery

Keep existing installation data safe.

Docker's standard named volume is a sensible default for a fresh installation. If you already use a bind mount or another volume, do not change its mapping without safely migrating the data.
