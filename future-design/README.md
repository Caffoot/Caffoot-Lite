# Milestone 01 — Interactive Planning Previews

> **Permanent reference archive — outside `main`.** This branch is intentionally retained to store reviewed Milestone 01 prototype files. **Do not merge it into `main`, publish it with a release, copy its styling into v2.1 screens, or delete it during ordinary branch clean-up.** At the start of Stage 2 and Stage 3 work, review the relevant archived HTML alongside the latest owner-approved issue requirements. Each new mock-up should be archived here only after the owner reviews it; the feature issues remain the source of truth for approved behaviour.

These are the **nine original standalone HTML files supplied by or reviewed with the product owner on 12–13 November 2026**, kept as review evidence and practical **functional interaction references only**.

**These are not application files, implementation authorisation, or additional/replacement pinned design sources.** The current v2.1 interface, the twelve pinned approved v2.1 HTML designs, and existing `interface/` styling and behaviour remain authoritative. Follow `CONTRIBUTING.md`. Add only independently approved new functionality **inside the existing v2.1 design**; never replace established screens with whole preview mock-ups or restyle unrelated controls. Preview data and access simulations are fictional and are not proof of backend security or persistence.

Where a file shows an earlier idea, later explicit product-owner decisions in the linked issues take precedence. The original file is preserved unchanged for traceability. **The functional previews cannot authorise changes to the existing approved v2.1 design**: new controls and assignments must be added to existing screens using their existing typography, layout, light/dark behaviour, accessibility and security rules. No Codex work, implementation, merge or release is authorised by archiving it.

## Stage 2 — Optional Features

**Authoritative issue:** [#238](https://github.com/Caffoot/Caffoot-Lite/issues/238). Stage 2 behaviour, integrated visual placement and final technical implementation plan were explicitly approved; development is paused until separately authorised.

- [Optional Features Integrated Settings Review](stage-2-previews/caffoot-optional-features-integrated-settings-review.html): approved functional interactions for the fourth **Settings & Data → Optional Features** tab, switches and disable confirmation. The existing three settings tabs, form controls, light/dark styling and layout must not change. [Visual sign-off](https://github.com/Caffoot/Caffoot-Lite/issues/238#issuecomment-6820547757).
- [Stage 2 IPAM and Device Details Review](stage-2-previews/caffoot-stage2-ipam-and-device-details-review.html): out-of-range basic-IP count in **IPAM Overview** and explicit **Link to IPAM** action from **Device Details**. **Only placement and functionality** are approved, not the different styling used in the preview. [Approval and strict v2.1 UI boundary](https://github.com/Caffoot/Caffoot-Lite/issues/238#issuecomment-6821121891).

An earlier standalone Optional Features mock-up was discussed in #238 but was **not supplied among these nine files**; this collection is not claimed to contain every earlier iteration.

## Stage 3 — Staff, IT Assets and Navigation

**Authoritative issues:** [#232 Staff & Departments](https://github.com/Caffoot/Caffoot-Lite/issues/232), [#352 IT Assets](https://github.com/Caffoot/Caffoot-Lite/issues/352), [#351 Milestone 01 Tracker](https://github.com/Caffoot/Caffoot-Lite/issues/351). Stage 3's entire visual and technical implementation plan is not yet signed off.

- [Assets Dashboard Preview](stage-3-previews/caffoot-assets-dashboard-preview.html): stock KPIs, readiness, registered vs unregistered stock, chart and movements. This early concept says **Assets**, later renamed **IT Assets** by [explicit owner approval](https://github.com/Caffoot/Caffoot-Lite/issues/352#issuecomment-6828024126). Final source-faithful integrated dashboard still needs review.
- [IT Assets — Receive Stock & Stock Item Readiness Review](stage-3-previews/caffoot-it-assets-receive-stock-ready-review.html): owner-approved functional direction 13 November 2026. Receive new stock or add a receipt to existing identical stock, recording quantities/specifications/condition checks; click an inventory stock item to inspect it and **later change how many awaiting-checks units are Ready To Issue**, without changing Physically Held, creating Devices, repeating the original receipt or overwriting history. Keep dated/attributed readiness events, validation, and reasoned correction of mistakenly ready units. **The owner requires functionality to be integrated into the accepted existing v2.1 UI, not to replace/restyle existing approved forms, navigation, tables or screens with this standalone HTML.** Original simpler Receive Stock draft lacked this edit step and is superseded by this accepted iteration. Precise implementation and source-faithful integrated styling, permissions and test sign-off are pending; no code integration/merge/Codex start has occurred.
- [IT & Staff Navigation Preview](stage-3-previews/caffoot-it-staff-navigation-preview.html): expandable groups, access demonstration and theme. This early iteration shows a separate **Users** entry, since superseded by **Staff → Permissions** under [final owner navigation approval](https://github.com/Caffoot/Caffoot-Lite/issues/232#issuecomment-6828925091).
- [Staff Member & Optional Login Preview](stage-3-previews/caffoot-staff-member-login-preview.html): Staff directory and combined Staff Member form with optional linked Caffoot login. The owner approved the **functional approach, explicitly conditional on preserving the actual v2.1 UI**, not treating this standalone appearance as a new design source. [Owner review](https://github.com/Caffoot/Caffoot-Lite/issues/232#issuecomment-6829687354).
- [Staff Directory & Equipment Assignments Preview](stage-3-previews/caffoot-staff-directory-assignments-preview.html): proposed searchable Staff Members directory and Staff Details interaction with assigned Devices, individually tracked IT Assets, quantity-based equipment, returns, reassignments, history and inactive Staff warnings. **Product owner likes and accepts this functional direction**, always **subject to retaining the approved current v2.1 UI without redesign**. The owner specifically found the **Devices page too difficult to assess from this preview**: **no approval is implied for any change to the existing Devices page layout or behaviour**. Prepare a clear source-faithful Devices-page integration review and obtain separate owner approval for any new Device-side controls or presentation.
- [Device Details — Assigned To Tab Review](stage-3-previews/caffoot-devices-assigned-to-tab-review.html): owner-reviewed 13 November 2026. **Functional direction accepted**: add a single **Assigned To** tab to the already-approved v2.1 Device Details tabs. Show current Staff/Department holder, issue date, authorised Issue/Return/Reassign actions and assignment history using the same canonical relationships as Staff and IT Assets. **No replacement, restyling, reorganisation or removal of any existing v2.1 Device Details tabs, inventory columns, Details button, controls or behaviour.** The underlying pinned Devices design remains authoritative; the preview is not pixel-perfect and its standalone styling is not a newly approved design. Exact technical/security integration and full source-faithful implementation review remain pending. Keep Codex paused.
- [Server Storage, ZFS Pools & Boot Drives Preview](stage-3-previews/caffoot-server-storage-zfs-boot-preview.html): reviewed 13 November 2026. **Functional additions accepted**: optional drive technology, Server Boot Storage for ZFS and non-ZFS computers, and ZFS named pools with constituent VDEVs and supported layout options. **Not a replacement form**: integrate only the necessary new fields within the *actual approved v2.1 Add/Edit Device form*, using its existing Hardware & Lifecycle / per-type detail conventions, visual styling, fields, validation, navigation, light/dark/responsive behaviour and established controls. Existing RAID must remain intact; the preview is **not exact visual approval** for its illustrative shell or a new layout. Data representation, validation and interactions still need source-faithful technical review. **No Codex start or implementation authorised.**

**Current agreed navigation:** expandable **IT** contains Devices, IT Assets, IPAM and Network Racks; expandable **Staff** contains Staff Members, Departments and admin-only Permissions. All existing effective permissions, independent optional-feature switches, MFA and account-management safeguards remain authoritative.
