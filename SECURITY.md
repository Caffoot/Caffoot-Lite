# Security Reporting

Thank you for helping keep Caffoot Lite safe.

## Report A Possible Vulnerability Privately

Please **do not** publish suspected vulnerabilities, working exploits, authentication credentials, personal data, API tokens, session cookies or other sensitive information in a public GitHub issue.

1. Open the repository's [Security page](https://github.com/Caffoot/Caffoot-Lite/security) and look under **Advisories** for GitHub's private vulnerability-reporting option.
2. **If "Report A Vulnerability" is available**, use it to share details privately with the maintainers.
3. **If that option is not available**, open a public issue entitled **Private Security Contact Requested**, containing **no vulnerability details, screenshots, exploits or secrets**. Ask the maintainers to provide an appropriate private reporting route before sending sensitive information.

Private vulnerability reporting is a repository feature that maintainers must enable in GitHub settings; the presence of this guide alone does not mean it is enabled.

For normal bugs that do not involve sensitive information, use the [Report A Bug form](https://github.com/Caffoot/Caffoot-Lite/issues/new/choose).

## What Helps In A Private Report

If a suitable private channel is available, share the affected Caffoot Lite version, a plain-language description of the problem, steps to reproduce it safely and its likely effect. Remove real passwords, authentication secrets and unrelated personal information.

Please allow maintainers to assess reports and agree an appropriate response before sharing sensitive technical details publicly.
